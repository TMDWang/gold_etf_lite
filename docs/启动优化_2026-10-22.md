# 启动优化验收记录

版本：0.1.1。日期：2026-10-22。此前其他 PWA 打开缓慢的根因未被诊断；本次修复的是本项目源码中已经确认的启动等待、请求超时和缓存缺失问题。

## 已实施

- 先显示通用页面框架；登录状态确认后，账户、行情、计划、提醒独立返回并显示。交易记录切到记录页才加载。
- 请求包含读取响应体的等待最长 12 秒；错误在对应区域显示重试。相同区域的普通轮询合并；成功写入后的刷新强制丢弃写入前的旧响应。
- 账号变化／退出／失效后，背景查询与直接设置、初始化等请求的迟到结果均不再更新页面；清理上一账号的表单及费用信息。
- 提醒关联成交必须取得相同计划及版本，计划尚未加载时禁止将其退化为无关联的手工成交。
- 复用 Workbox 生成页面框架缓存，仅含通用根页面、脚本、样式、图标和安装清单；所有个人 API 不进入 Cache Storage，不创建离线交易队列。
- 新版等待本人点击“更新页面”，填写表单及提交期间不出现更新按钮；原有微信提醒机制继续在 NAS 后台运行。
- 图表按需加载：主脚本构建体积由约 829 KB 降到约 343 KB，图表另约 497 KB；构建体积不等于实际网络时延承诺。

## 验证证据

- 前端 18 项测试通过，包含慢区域不阻塞快区域、请求超时、旧会话迟到结果、写入后防旧值覆盖，以及提醒不得失去计划关联。
- Django 后端 40 项测试中 37 项通过；3 项 PostgreSQL 真实并发测试在本机明确跳过。
- 生产前端构建及 Workbox 6 项资源预缓存生成成功；生成清单仅包含根页面与 `/static/` 文件，没有 `/api/`。
- 浏览器故障测试：人为让行情接口等待 20 秒，现金／份额等区域仍正常显示；超时仅影响行情区域。
- 浏览器断开实测：停止本地应用服务，重新加载页面仍能从缓存打开“暂时无法连接账本”及“重新连接”按钮，未显示资金、未离线提交成交。
- 浏览器更新按钮实测：新版安装后提示更新，点击完成切换；服务恢复后可点击重新连接。
- 本地演示使用虚构账目；没有发送真实 PushPlus 测试消息；未运行 GitHub Actions。

## 审阅与限制

独立代码检查发现了写入后旧响应覆盖、提醒过早确认造成失去计划关联、失效会话的设置请求重新打开弹窗三项问题，均已补回归测试并修复。独立审阅随后因服务额度中断；最终修复由执行者运行全套测试验证，没有宣称完成第二轮独立审阅。

这不能证明所有手机系统、PWA 安装方式、NAS 网络或 Cloudflare 隧道的实际打开速度。NAS 容器启动、盘中免费双源时效、微信真实送达及 PostgreSQL 备份恢复，仍需部署后按原验收说明检查。系统清理缓存后需要重新联网，个人资金始终依赖在线身份核验。
