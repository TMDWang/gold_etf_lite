# 日常使用优化

目标是让用户清楚地查看资产、理解提醒、试算成交、核对流水，并能在 NAS 上维护服务。

用户已同意全部推荐并授权自行处理细节。继续使用 Django、PostgreSQL、Vue、Vant、现有 Docker 与 PushPlus。个人数据按登录用户隔离，公共群消息仅使用公共信息。价格变化使用现有 SSE，其他内容在打开、操作后或主动刷新时读取。

## 已确认的账务规则

- 继续按记账顺序计算，纠错替换原位置的有效数据。
- 历史资金变动保留为未分类，资产正常显示，受影响的投资收益标记待核对。
- 新资金变动可选转入、转出、分红收入、账户费用、未分类，分类与金额方向须一致。
- 每日报表按北京时间 15:00 的记账状态估值。补录计入实际登记日，成交时间仍保存。纠错产生新报表版本。
- 收盘附近采样明确标明来源、时间和采样估值性质，缺少有效收盘附近行情时留空。初始化晚于收盘的日期不生成收盘资产。
- 日收益从相邻交易日报表扣除期间净转入资金计算。缺少前一日报表或期间资金未分类时显示待核对。

## 实施步骤

1. 复用账本重算增加只读一致性检查、成交影响预览及过期版本校验。验证原始记录和纠错链、补录、重复提交与本人权限。
2. 增加资金分类、每日资产报表及报表版本。定时补齐遗漏日期，支持本人主动刷新。验证跨日资金、缺行情、现金账户和纠错修订。
3. 增加规则状态说明、今日或定时暂停、提醒历史。监测和最终发送均校验暂停，保留推送结果未知时的处理规则。
4. 增加交易日期、方向和纠错筛选及有效流水金额汇总。记录页与导出使用同一筛选规则。
5. 使用现有 Vue/Vant 增加账目检查、日报、筛选、提醒状态与历史、首次使用清单、试算依据。个人动态状态仅保存在当前页面内，退出清除。
6. 增加采集成功时间与心跳状态、维护诊断和故障恢复记录。备份使用独立锁，减少相互阻塞。
7. 运行后端回归、迁移检查、前端测试和构建。使用虚构账户检查页面与表单保留、刷新和退出。发布语义版本并同步 GitHub。

## 重点检查

- 异常账本只报告差异，普通读取不会自动修账。
- 财务预览和最终写入都使用相同的 Decimal 舍入与交易单位规则。
- 筛选按记账日期，汇总使用有效纠错值，修订记录不会重复计入金额。
- 报表估值不以其他日期的报价补缺，历史资金分类不进行推测。
- 暂停提醒在 HTTP 发送前再次校验。公共历史只包含公共规则和公共行情。
- SSE 心跳携带少量公共采集状态，未变价格继续省略报价推送。
- NAS 与 Cloudflare 实际长时间连接需要部署后验证，本地测试记录范围明确。

## 验证记录

- 后端共 112 项，108 项通过，4 项需要 PostgreSQL 的并发专项在本机跳过。
- 前端 59 项测试通过，生产构建及页面缓存构建通过，迁移检查无遗漏。
- 独立只读审查发现的三个问题已用回归测试复现并修复。确认期间修改输入会作废该次操作，筛选 CSV 提供有效方向和时间，旧轮次的忽略操作只作用于目标轮次。
- 实际页面使用独立数据库及虚构账户验证了 390 像素布局、账目核对、日报、筛选、暂停、提醒历史和预览保留。虚构买入从 500 份变为 700 份，现金从 11038 元变为 10133 元，与确认页一致，入账后再次核对一致。
- 费用估算按钮直接读取服务器保存的个人规则，使用现有 Decimal 舍入。费用未填写时，前端提示补齐信息。
- 本次版本为前后端 v0.6.0。NAS Docker 与 Cloudflare 隧道的实际长时间稳定性仍需部署后确认。
