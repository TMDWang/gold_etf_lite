# 前后端职责与资源策略

## 前端

前端负责页面布局、表单输入、图表绘制和结果展示，以及基础输入提示。买入预览的最终金额由后端计算，前端不自行修改账本。买入预览打开期间，等待中的页面更新会推迟到表单关闭后；模拟输入和结果只在当前页面内存中，不写入离线缓存，页面意外重载后需重新填写。

前端在当前标签页内短暂复用成功的接口结果。登录且页面可见时通过 SSE 接收公共行情，并仅更新价格、曲线最新点及以此计算的展示值。切换页面、回到前台、恢复联网或用户操作后获取必要的动态数据；个人账户、计划和记录不做后台定时轮询。账本和计划变更后，中止旧的未完成请求并强制更新当前页面，其他页面下次访问时重新获取；单条提醒设置会刷新相应区域。网络请求失败时保留已显示数据并提示，不把旧数据当成新请求成功。退出或登录失效时清除页面内个人数据及复用状态。

SSE 连接异常或长时间没有心跳时，前端使用行情接口获取快照，并约每 30 秒尝试重新建立连接；恢复后停止回退请求。打开的页面中，个人提醒列表不会实时推送，切换页面、回到前台或操作时才同步；PushPlus 后台通知仍独立运行。

## 后端

后端负责登录与权限校验、账号数据隔离、定点金额计算、账本和纠错、计划与提醒规则、行情采集和数据校验、定时监测及 PushPlus 推送。所有写入以服务端校验为准；买入预览只读取当前账户并计算，不写入账本。

账户接口返回最新参考价及源时间，用于持仓页及预览。持仓页无需下载完整分时曲线；首页才请求曲线。系统不因缓存而忽略行情有效性，提醒仍由后端在有效交易时段依据有效行情检查。

应用使用 Django ASGI 和 ServeStatic，仍由同一 Docker 应用服务运行。每个应用进程最多维护一个共享行情读取任务，每 5 秒检查已有行情数据，连接共享结果，不会为每位用户重复请求行情源。流中只有公共行情和心跳，不包含账户、持仓或交易记录；会话定期重新验证。免费行情的采集频率仍约为 60 秒，SSE 不代表逐笔实时行情。

价格相同时不重复推送价格；开休市或行情有效性发生变化时只发送状态，避免误显示。页面重新打开或重连时获取最新快照。曲线最高价和最低价来自当前已取得的采样点，不保证等于交易所当日实际最高价和最低价；未推送的相同价格不会补画成新的曲线点。

## 静态与动态资源

- 在线首页始终发起网络请求，首页 HTML 与 Service Worker 脚本使用 HTTP `no-store`。Service Worker 另行预缓存公共离线页面，在首页网络请求失败时回退。版本化的 CSS、入口脚本和图标继续缓存。
- 分时图脚本按需下载，首次需要图表时才缓存，最多保留两个版本；缓存只匹配同源的图表脚本路径。
- 所有 `/api/` 请求为动态数据，服务端返回 `Cache-Control: no-store, private`；Service Worker 不缓存 API 响应。当前页内复用是内存状态，不是设备离线存储。
- 实际节省量取决于用户访问页面和行情数据量；静态资源首次下载、版本更新、缓存被系统清理或网络连接本身仍需流量。
